# PiLog – Domain Glossary

| Term                                   | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Note**                               | A raw, unstructured piece of text captured by the developer. Notes live in the Inbox until processed. Statuses: `unprocessed`, `drafted`, `published`, `dismissed`. When a drafted note is opened from the Inbox, its primary continuation is the current Issue Draft derived from it; if later split/merge work leaves multiple current drafts associated with the note, the Inbox should present a multi-draft fallback instead of treating the Agent Run as the primary target. A note should only show **View draft** when an actual Issue Draft contains that note; run-only states remain secondary provenance.                                                                                                                                                                                                                                                        |
| **Inbox**                              | The primary screen listing all captured notes, ordered newest-first. The starting point for triage and issue generation. The Inbox owns source-note review and lightweight note metadata; it should navigate to Draft Review for generated Issue Draft inspection instead of embedding a parallel single-draft reviewer. Inbox and Drafts form the primary top-level workspace loop; audit/history surfaces such as Run History should not appear as peer primary tabs.                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Repo**                               | A local Git repository linked to PiLog. Used to provide file/context awareness when generating issue drafts.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Issue Draft**                        | A structured GitHub-issue-shaped document generated by the agent from one or more notes. Statuses: `draft`, `published`, `dismissed`. A source note's **View draft** continuation remains valid across all three statuses; opening it should select the relevant draft even when that draft lives behind the Published or Dismissed review filter.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Agent Run**                          | A single invocation of `agent.prompt()` against PiLog's embedded Pi runtime, triggered by clicking **Generate Drafts** on a selection of notes that share a single linked repo. Produces zero-or-more Issue Drafts and is recorded with a Run Status. In note detail surfaces, the Agent Run is provenance and audit history; when an Issue Draft exists, the draft is the note's primary continuation and the run belongs in secondary metadata such as the footer/meta rail. Agent Runs are not a primary workspace alongside Inbox and Drafts; they are contextual audit/history reached from notes, drafts, failed-run notices, command/search, or advanced history surfaces. When opening a run from a work surface, PiLog should preserve that origin so the run view can show an origin-aware breadcrumb back to the note, draft, or history surface that exposed it. |
| **Publish Log**                        | An immutable record of every issue draft that was published to GitHub, including the resulting issue URL and timestamp.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Scratchpad**                         | (Future) A lightweight, always-on-top markdown editor invoked via global hotkey for instant note capture. Not implemented in this slice.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Settings**                           | A key/value store for user preferences (hotkey, default mode, auto-publish flags, etc.).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Pi**                                 | The open-source TypeScript agent framework from [`earendil-works/pi`](https://github.com/earendil-works/pi). PiLog embeds Pi as a library by importing `@earendil-works/pi-agent-core` and `@earendil-works/pi-ai` directly into the Electron main process. The standalone `pi` CLI is never invoked. See ADR-0005.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Active Provider** / **Active Model** | The user's selected `{ provider, modelId }` pair, surfaced in **Settings → Provider & Model** (see #13). Provider/model identifiers are persisted in `pilog.sqlite`'s `settings` table; credentials live in `safeStorage`. Required (non-null with a configured credential) before **Generate Drafts** is enabled.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Run Status**                         | The terminal state of an Agent Run. One of `running` (in-flight), `succeeded` (the agent called `submit_issue_drafts` with a valid payload and persistence committed), `failed` (any error other than user cancellation; carries a classified `errorCause`), or `cancelled` (user-initiated abort or window-closed-mid-run). Each terminal state has a distinct UX surface.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Run History**                        | The complete secondary audit surface for Agent Runs. It preserves provider/debug history, failures, zero-draft runs, transcripts, and run outputs, but it is not part of the primary Inbox → Drafts work loop. It is reachable from contextual run links, the command palette, Settings/Advanced, or other audit/history affordances; when opened generically, breadcrumbs should root at **Run history**. Run/history routes should show breadcrumbs in the top-left app chrome instead of the primary Inbox/Drafts switcher. Breadcrumbs should stay navigational; run status, duration, output counts, and error cause belong in the run detail content header. Generic history entry points should open the full run list with the latest run selected; contextual run links should open the referenced run directly.                                                    |
| **Command Palette**                    | The global keyboard-first command and search surface. It should be available from every primary workspace and secondary route, not only Inbox. Global commands include navigation such as **Open run history**; active surfaces may contribute contextual results such as note search, draft search, or current-selection actions. The initial global search scope is Notes, Issue Drafts, and Commands; raw Agent Run log/result search should remain out of scope unless promoted by a later audit-history decision.                                                                                                                                                                                                                                                                                                                                                       |
| **Turn Budget**                        | The maximum number of agent turns (one LLM response + its tool calls) a single Agent Run is allowed before being terminated as `failed` with `errorCause: 'turn_budget_exceeded'`. Default 20; tunable per-user via **Settings → Advanced**, persisted in the `settings` table under `pi.turnBudget`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Web Search**                         | An opt-in network capability that registers a `web_search` tool against the agent. Off by default. When enabled, the user configures a search provider (Brave, Tavily, etc.) whose API key is stored via `safeStorage`. Returns structured URL + title + snippet results only; PiLog does not register a `web_fetch` tool that retrieves arbitrary URL contents.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
